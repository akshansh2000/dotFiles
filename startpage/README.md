# startpage

The Firefox new tab page, served over loopback so **Tridactyl bindings work on
it**.

## Why a web server and not a file or an extension

Both of the obvious approaches are dead ends:

- **`file:///…`** — Tridactyl's own docs for the `newtab` setting: *"don't try
  `about:newtab` or a `file:///` URI. You can instead host a local webserver."*
- **A newtab-override extension** — Tridactyl's `content_scripts.matches` is
  `<all_urls>`, which covers http/https/file/ftp/data but **not
  `moz-extension://`**. Firefox does not let one extension inject into another's
  pages, so our page would get zero Tridactyl bindings. Tridactyl's own newtab
  page works only because it is Tridactyl's page. On top of that, Tridactyl
  already claims `chrome_url_overrides.newtab`, so a second extension would be
  fighting it for the slot.

Over `http://` the content script loads normally and everything works.

    new tab → Tridactyl newtab.html → redirect → http://127.0.0.1:8123

## Layout

| Path | |
|---|---|
| `index.html.tmpl` | **edit this** — markup plus the CSS, inline; `{{PLACEHOLDER}}`s come from `~/.config/theme/` |
| `index.html` | generated by `~/.config/theme/apply-theme.sh` — do not edit |
| `script.js` | clock/date |
| `~/.local/sv/startpage/run` | the server, supervised by the user `runsvdir` |

Colours follow `~/.config/theme/colors.sh` like everything else in the rice:
change the palette, run `apply-theme.sh`, reload the tab.

**The CSS lives inside the page on purpose** (since 2026-09-30). It used to be a
separate `style.css`, which arrived after Firefox's first paint: a
frame-by-frame screen recording showed the page unstyled (white background,
black serif links) for ~90–100 ms on every new tab and new window, even though
darkhttpd served the file in 8 ms. Inline styles are parsed before the first
paint, so that flash cannot happen. Don't split it back out.

## Keys

The page binds **nothing** — Tridactyl owns the keyboard here:

| key | |
|---|---|
| `gi` | focus the search box |
| `f` | hint the links |
| `o` / `t` | open in this / a new tab |

The search field has no `autofocus` on purpose. With it, every new tab would
land in insert mode and swallow `f`, `o` and `gt`.

## Wiring (one-time, in Firefox)

    :set newtab http://127.0.0.1:8123

That lives in extension storage. To make it reproducible, install the native
messenger (`:installnative`) and put it in `~/.config/tridactyl/tridactylrc`.

`allowautofocus` is deliberately left at its default (`true`). This page never
autofocuses anything, so turning it off bought nothing and cost the username
field on every login form.

## The Ctrl+T annoyance

`Ctrl+T` leaves focus in the address bar with the localhost URL pre-filled.
`t` / `:tabopen` / `:open` do not. Three facts, none of them convenient:

- There is **no Firefox pref** for new-tab focus.
- Tridactyl's `newtabfocus` setting was **removed in 1.20.0** as broken
  ([#2632](https://github.com/tridactyl/tridactyl/issues/2632)), and 1.25.1 is
  current — so this is not fixed by upgrading.
- `Ctrl+T` is a reserved browser shortcut; extensions cannot rebind it.

The Tridactyl maintainer's own answer
([discussion #4967](https://github.com/tridactyl/tridactyl/discussions/4967))
is *"open tabs directly with `t` / `:tabopen` rather than ctrl+t"*.

**Settled: use `t`.** A page-side focus grab was tried and reverted on
2026-09-10 — `document.body.focus()` did not beat the address bar, and giving
the body a `tabIndex` made Tridactyl treat the whole page as a focused input
and paint it bright yellow. Don't try it again.

The only fix reported working is AutoConfig, and it is not worth it:

`/usr/lib/firefox/defaults/pref/autoconfig.js`

    pref("general.config.filename", "mozilla.cfg");
    pref("general.config.obscure_value", 0);
    pref("general.config.sandbox_enabled", false);

`/usr/lib/firefox/mozilla.cfg` — **the first line must be a comment**, it is
skipped:

    //
    Services.obs.addObserver((event) => {
      BrowserWindowTracker.getTopWindow().gBrowser.selectedBrowser.focus();
    }, "browser-open-newtab-start");

Both files live in the package's install prefix, so a `firefox` update wipes
them; and `sandbox_enabled false` switches off a hardening measure. Since `t`
already does the right thing, this stays unimplemented.
